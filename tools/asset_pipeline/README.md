# Asset pipeline backend

Python backend for Asset Studio (see #222, decisions in #220). Run from this directory with `uv run asset <command>`, or from the repo root with `uv run --project tools/asset_pipeline asset <command>`. Every command prints one JSON object (`{"ok": true, ...}` or `{"ok": false, "error": ...}`).

Implemented: `concept <slug> [--n 3] [--brief TEXT] [--image-provider P] [--prompt-writer W] [--refine VARIANT --notes TEXT]`, `turnaround <slug>` (front, left, back, right, 2048 px, reference-conditioned edits of the locked concept), `brief <slug>` (writes `assets/models/<slug>/concept/brief.md`), `new <slug> --class <creature|prop|architecture|terrain> [--issue N]` and `lock <slug> <variant> [--decision approved|rejected] [--reviewer NAME] [--notes …]`. `cleanup <slug> --source <run> [--size-m M] [--triangle-budget N]` (headless Blender, below), `doctor [--live]` checks the Blender, Godot and Claude CLI paths and the API keys (exit 1 if a required check fails). The remaining stages arrive in later arcs.

- Manifest: `assets/models/<slug>/asset.yaml` (committed): stage, lineage (prompt, provider, model, parent of every image or mesh), the locked variant and reviewer decision.
- Scratch: `.asset_work/<slug>/` (git-ignored): rejected variants and raw provider meshes.
- Providers: `providers.yaml` picks a provider per kind (`image`, `three_d`, `prompt_writer`); commands override with a flag. Images: `mock` (deterministic fixtures), `openai` (GPT Image, `OPENAI_API_KEY`), `google` (Nano Banana, `GEMINI_API_KEY`) and `fal` (any fal.ai endpoint such as FLUX, Seedream or Recraft, `FAL_KEY`), one file each under `asset_pipeline/adapters/`. Reference images go up as multipart files (OpenAI), inline data (Google) or data URIs in `image_urls` (fal). A new provider on an existing adapter is a `providers.yaml` entry with `adapter: <name>` and the model; no command changes. 3D: `mock`, `tripo` (`TRIPO_API_KEY`), `meshy` (`MESHY_API_KEY`), `rodin` (`RODIN_API_KEY`, model is the tier) and `trellis` (TRELLIS.2 on fal's queue API, `FAL_KEY`; the model is the endpoint id). Each takes the four turnaround views, submits, polls and downloads the GLB. Hunyuan3D is not shipped (licence excludes EU, UK, South Korea; #219). `asset to3d <slug> --3d-provider tripo meshy` runs the latest turnaround through each provider (the bake-off), writes raw GLBs to `.asset_work/<slug>/to3d/` and records each as a `mesh` lineage entry with provider, model id and task id; a provider that fails is listed under `errors` and does not stop the others (`--poll-interval`, `--timeout` tune the wait). Tests replay recorded HTTP fixtures against a loopback server, and `conftest.py` fails any test that opens a non-loopback connection.
- PromptWriter (`--prompt-writer`): `mock`; `claude-cli` runs `claude -p … --output-format json` with `--allowedTools Read` and `--add-dir` for the images, using your Claude Code login or `CLAUDE_CODE_OAUTH_TOKEN` (set `ASSET_CLAUDE_BIN` for a non-PATH binary); `anthropic-api` calls the Messages API with `ANTHROPIC_API_KEY` only. The OAuth token is never used in Messages API calls. Model comes from `providers.yaml`.
- Concept prompts are the style bible block, the writer's prompt and the negative block; 2 to 4 anchors from `assets/style_bible/anchors/<class>/` are passed as references on every concept call (a refine also passes its parent). Variants go to `.asset_work/<slug>/concept/`; each manifest lineage entry records prompt, provider, model, writer, references and parent.
- Keys: environment variables, loaded from `tools/asset_pipeline/.env` (git-ignored). Never commit them.
- Tests: `uv run pytest`.

- Cleanup (`asset cleanup <slug> --source r1_tripo`): runs `blender -b --factory-startup -P asset_pipeline/blender/cleanup_bpy.py` on a raw mesh from `to3d`, applying the class profile's `cleanup_recipe` in order from `assets/style_bible/classes.yaml`: `repair` (weld, drop degenerate faces and stray parts, fill holes, fix winding), `scale_and_pivot` (largest dimension to the brief's metres, pivot at bottom centre), `snap_to_grid`, `decimate_to_budget` or `remesh_to_budget` (a re-repair follows, so the result stays manifold), `flat_shade`, `vertex_colour_palette` (the noisy baked colours become at most `palette_size` flat colours, one per face) and `collision_helper` (a convex hull, or a trimesh for terrain, named `<slug>_collision-convcolonly` / `-colonly` so Godot imports it as a shape). The size comes from `--size-m`, else a `size_m: 2.5` line in `brief.md` (the largest of up to three numbers), else the middle of the class's scale range. Output: `.asset_work/<slug>/cleanup/c<k>.glb`, a `mesh` lineage entry (provider `blender`, parent the source) and a `cleanups` record in the manifest: source, recipe, parameters, the git commit of the code that ran it, a digest of the Blender script and the measured triangles, non-manifold count, vertex colours and size. Blender 4.5 LTS is found through `ASSET_BLENDER_BIN` (shell or `.env`), else `blender` on `PATH`; without it `cleanup` fails with a clear error, `doctor` reports `blender` as missing and the Blender-backed test skips. CI installs and caches it with `.github/actions/setup-blender`.
- Fixture: `python -m asset_pipeline.fixture_mesh out.glb` writes the ~100k-triangle noisy coloured mesh (lumpy ellipsoid, per-vertex colour noise, duplicated seam, stray fragment) that `tests/test_cleanup.py` cleans; `fixture_mesh.read_glb` reads the result back without Blender so the test checks budget, manifold, colours, scale and pivot independently.
