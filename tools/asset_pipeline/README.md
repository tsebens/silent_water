# Asset pipeline backend

Python backend for Asset Studio (see #222, decisions in #220). Run from this directory with `uv run asset <command>`, or from the repo root with `uv run --project tools/asset_pipeline asset <command>`. Every command prints one JSON object (`{"ok": true, ...}` or `{"ok": false, "error": ...}`).

Implemented: `concept <slug> [--n 3] [--brief TEXT] [--image-provider P] [--prompt-writer W] [--refine VARIANT --notes TEXT] [--reference IMAGE …] [--mode paint-over|inspire]`, `turnaround <slug> [--view front|left|back|right|top|bottom]` (the views in the class's `turnaround_views` in `classes.yaml`, default front, left, back, right and all six for `creature`; 2048 px, reference-conditioned edits of the locked concept, with straight-down and straight-up orthographic prompts for `top` and `bottom`; `--view` regenerates one view into a new complete `t<n>` set, copying the others from the latest set (a `top` or `bottom` it lacks is added), so `brief`, `to3d` and `check` keep reading one latest set), `brief <slug>` (writes `assets/models/<slug>/concept/brief.md`), `new <slug> --class <creature|prop|architecture|terrain> [--issue N] [--description TEXT]`, `describe <slug> TEXT` (sets or replaces the description, the concept brief `concept` reads without `--brief`; `--brief` still overrides and saves) and `lock <slug> <variant> [--decision approved|rejected] [--reviewer NAME] [--notes …]`. `cleanup <slug> --source <run> [--size-m M] [--triangle-budget N]` (headless Blender, below), `doctor [--live]` checks the Blender, Godot and Claude CLI paths (and that Blender is 4.5.x and Godot 4.7.2 standard, non-.NET, per `versions.yaml`) and the API keys (exit 1 if a required check fails). `check <slug> [--source MESH] [--size-m M] [--triangle-budget N]` (numeric gates, below). `godot-check <slug> [--source MESH] [--log-dir D] [--no-render]` and `export <slug> [--source MESH]` are described in [docs/asset_pipeline.md](../../docs/asset_pipeline.md). The remaining stages arrive in later arcs.

- Manifest: `assets/models/<slug>/asset.yaml` (committed): stage, lineage (prompt, provider, model, parent of every image or mesh), the locked variant and reviewer decision.
- Scratch: `.asset_work/<slug>/` (git-ignored): rejected variants and raw provider meshes.
- Providers: `providers.yaml` picks a provider per kind (`image`, `three_d`, `prompt_writer`); commands override with a flag. Images: `mock` (deterministic fixtures), `openai` (GPT Image, `OPENAI_API_KEY`), `google` (Nano Banana, `GEMINI_API_KEY`) and `fal` (any fal.ai endpoint such as FLUX, Seedream or Recraft, `FAL_KEY`), one file each under `asset_pipeline/adapters/`. Reference images go up as multipart files (OpenAI), inline data (Google) or data URIs in `image_urls` (fal). A new provider on an existing adapter is a `providers.yaml` entry with `adapter: <name>` and the model; no command changes. 3D: `mock`, `tripo` (`TRIPO_API_KEY`), `meshy` (`MESHY_API_KEY`), `rodin` (`RODIN_API_KEY`, model is the tier) and `trellis` (TRELLIS.2 on fal's queue API, `FAL_KEY`; the model is the endpoint id). Each entry takes `views:` (default front, left, back, right; any of front, left, back, right, top, bottom), the turnaround views `to3d` sends it, in that order, skipping any the asset lacks: `trellis-multi` sends all six, `trellis` front only, Tripo, Meshy and Rodin the four. Each submits, polls and downloads the GLB.

- 3D views and options: `asset to3d <slug> --3d-provider P [--views left | left,front,top] [--option key=value ...]`. `--views` sends exactly those turnaround views in that order; a provider takes at most its `max_views` (a `providers.yaml` field; adapters default it: `trellis` with `input: single` 1, Tripo and Meshy 4, Rodin 5, `trellis-multi` 8), and more is an error naming the limit. Without `--views` the views are, in order: the provider entry's `views:`, the class's `to3d_views` in `classes.yaml`, then front, left, back, right; each cut to `max_views`. A provider entry may carry `options:`, a mapping merged into its request body (a multipart field for Rodin); `--option` (repeatable, values read as YAML so `1024` is a number) wins for one run. `trellis` ships with `resolution: 1024` (fal accepts 512, 1024, 1536); for `trellis-multi`, `multiimage_algo` is left at its default `stochastic`, and `--option multiimage_algo=multidiffusion` tries the other. The `mesh` lineage entry records `views` (the turnaround lineage ids sent, in order) and `options` (as sent); older manifests lack both and load unchanged. `prices.yaml` may price by an option: `by_option: resolution`, `usd: {512: 0.25, 1024: 0.30, 1536: 0.35}` and `option_default` for an option not sent; the ledger and `--estimate` use the options actually sent, and an unlisted value is `unknown`.
 Hunyuan3D is not shipped (licence excludes EU, UK, South Korea; #219). `asset to3d <slug> --3d-provider tripo meshy` runs the latest turnaround through each provider (the bake-off), writes raw GLBs to `.asset_work/<slug>/to3d/` and records each as a `mesh` lineage entry with provider, model id and task id; a provider that fails is listed under `errors` and does not stop the others (`--poll-interval`, `--timeout` tune the wait). Tests replay recorded HTTP fixtures against a loopback server, and `conftest.py` fails any test that opens a non-loopback connection.
- PromptWriter (`--prompt-writer`): `mock`; `claude-cli` runs `claude -p … --output-format json` with `--allowedTools Read` and `--add-dir` for the images, using your Claude Code login or `CLAUDE_CODE_OAUTH_TOKEN` (set `ASSET_CLAUDE_BIN` for a non-PATH binary); `anthropic-api` calls the Messages API with `ANTHROPIC_API_KEY` only. The OAuth token is never used in Messages API calls. Model comes from `providers.yaml`.
- Reference images: `concept --reference IMAGE` (repeatable; PNG, JPEG or WebP) works from your own image, such as a blockout render or a sketch. `--mode paint-over` (the default with a reference) tells the writer to keep the reference's composition, camera, proportions and major shapes and change only materials, detail, colour and lighting; the reference goes to the provider's **edit** path as the source image, with the style anchors as extra references. `--mode inspire` treats it as a loose starting point and uses plain generation with the reference added to the anchors. Each reference is hashed (SHA-256 of the original file), converted to PNG, scaled so its longest side is at most the image provider's `max_input_px` (2048) and copied to `.asset_work/<slug>/references/<hash12>.png`. With several references, `--n` variants are made **per reference** (the writer runs once per reference), so `--reference a.png --reference b.jpg --n 2` makes 4. Each variant's lineage entry has `reference: {name, sha256}` (the original file name only, never its path) and `mode`, and its `references` list names the stored copy. `refine` of a paint-over variant re-passes the same stored reference (`--reference` does not combine with `--refine`); refining an inspire variant does not. `--estimate` and the ledger count one image generation per variant, and one writer call per reference.
- Concept prompts are the style bible block, the writer's prompt and the negative block; 2 to 4 anchors from `assets/style_bible/anchors/<class>/` are passed as references on every concept call (a refine also passes its parent). Variants go to `.asset_work/<slug>/concept/`; each manifest lineage entry records prompt, provider, model, writer, references and parent.
- Keys: environment variables, loaded from `tools/asset_pipeline/.env` (git-ignored). Never commit them.
- Tests: `uv run pytest`.
- Cost ledger: every paid backend call appends an entry to the manifest's `costs` list: `at`, `command`, `stage` (`concept`, `refine`, `turnaround`, `brief`), `provider`, `model`, `lineage` (the id it produced, if any), `units` (usage as the provider reported it: `input_tokens`, `output_tokens`, `total_tokens`, `images`, later `credits`), `usd`, `basis`, `unit_price` (the rates used, so a price change never rewrites history), `api_equivalent_usd` and `error`. `basis` is `reported` (the provider returned a cost or credit charge), `estimated` (reported usage, or the request, times `prices.yaml`), `mock` (always 0), `unknown` (`usd: null`, never silently 0) or `subscription` (`claude-cli`: `usd: 0`, with `claude -p`'s API-equivalent cost kept in `api_equivalent_usd`, and never counted as spend). OpenAI and Google are priced from the token counts in their replies, fal per image, `anthropic-api` from token usage. The list is append-only: reject, delete and regenerate never remove entries. A call that fails after the provider reported usage (billed, no usable image) is recorded with `error`; one that fails before any usage (auth, HTTP, network) is not. A command that fails part-way still writes the entries it added. Prices are in `tools/asset_pipeline/prices.yaml` (per provider and model, with source URL and date checked); the figures shipped are unverified placeholders, and each credit-based provider's `usd_per_credit` has a comment naming the plan it assumes, which a test enforces. `to3d` records one entry per provider run (`stage: to3d`, `units.generations: 1`, `lineage` the mesh run id), so a bake-off adds one entry per provider. A job counts as billed once the provider accepted it: if it then fails or times out, the entry is still recorded with `error`; a rejected submit records nothing. Tripo reports the task's `consumed_credit`, which is recorded as `units.credits` (basis `reported`, times the plan's `usd_per_credit`). Meshy, Rodin and fal Trellis responses carry no charge, so they are `estimated` from `prices.yaml`: `credits_per_generation` times `usd_per_credit` for Meshy and Rodin, `usd_per_generation` for Trellis. `asset cost <slug>` prints the asset's total USD, `reported_usd` and `estimated_usd` totals, `by_stage` and `by_provider` (USD, count, unknown count; `subscription` entries are not spend) and an `unknown` list of entries that could not be priced; `asset cost --all` prints per-asset totals and a grand total over every manifest. `--estimate` on `concept`, `turnaround`, `brief` and `to3d` prints `estimate: {usd, calls, unknown}` from `prices.yaml` and the request (variants, views, providers) and calls and writes nothing; a call with no flat price (a paid prompt writer, a model missing from the table) is listed under `unknown`, never counted as zero. A soft budget, `budget_usd`, can be set per class in `assets/style_bible/classes.yaml` and per asset in the manifest (the asset's wins): when the total passes it `asset cost` adds a `warning`, and nothing is blocked. The plugin views come in a later arc of #267.
- Paths: every path stored in a manifest or printed in command JSON or a check report is repo-relative with forward slashes (`paths.posix_rel`); a manifest holding backslashes loads normalised. A `windows-latest` CI job runs `tests/test_posix_paths.py`.

- Cleanup (`asset cleanup <slug> --source r1_tripo`): runs `blender -b --factory-startup -P asset_pipeline/blender/cleanup_bpy.py` on a raw mesh from `to3d`, applying the class profile's `cleanup_recipe` in order from `assets/style_bible/classes.yaml`: `repair` (weld, drop degenerate faces and stray parts, fill holes, fix winding), `scale_and_pivot` (largest dimension to the brief's metres, pivot at bottom centre), `snap_to_grid`, `decimate_to_budget` or `remesh_to_budget` (a re-repair follows, so the result stays manifold), `flat_shade`, `vertex_colour_palette` (the noisy baked colours become at most `palette_size` flat colours, one per face) and `collision_helper` (a convex hull, or a trimesh for terrain, named `<slug>_collision-convcolonly` / `-colonly` so Godot imports it as a shape). The size comes from `--size-m`, else a `size_m: 2.5` line in `brief.md` (the largest of up to three numbers), else the middle of the class's scale range. Output: `.asset_work/<slug>/cleanup/c<k>.glb`, a `mesh` lineage entry (provider `blender`, parent the source) and a `cleanups` record in the manifest: source, recipe, parameters, the git commit of the code that ran it, a digest of the Blender script and the measured triangles, non-manifold count, vertex colours and size. Blender 4.5 LTS is found through `ASSET_BLENDER_BIN` (shell or `.env`), else `blender` on `PATH`; without it `cleanup` fails with a clear error, `doctor` reports `blender` as missing and the Blender-backed test skips. CI installs and caches it with `.github/actions/setup-blender`.
- Fixture: `python -m asset_pipeline.fixture_mesh out.glb` writes the ~100k-triangle noisy coloured mesh (lumpy ellipsoid, per-vertex colour noise, duplicated seam, stray fragment) that `tests/test_cleanup.py` cleans; `fixture_mesh.read_glb` reads the result back without Blender so the test checks budget, manifold, colours, scale and pivot independently.

- Check (`asset check <slug>`): gates the latest cleanup (or `--source <mesh id>`) in pure Python, no Blender or renderer. Gates, with thresholds from the class's `gates` block in `classes.yaml`: `triangles` (count against `triangle_budget` x `triangle_tolerance`), `bbox` (largest dimension against the brief's `size_m`, within `bbox_tolerance`), `loose_parts` (connected parts, vertices welded by position, at most `max_loose_parts`), `non_manifold` (edges not shared by exactly two faces, so holes count; faces collapsed by welding are ignored; at most `max_non_manifold`) and `silhouette_front|left|back|right` (plus `silhouette_top` and `silhouette_bottom` only when the turnaround has those views; IoU of the mesh projected orthographically against the latest turnaround's view, at least `silhouette_iou_min`). Collision helper nodes (`-colonly`, `-convcolonly`) are left out of every measurement. Silhouettes: the asset faces +Z; front is seen from +Z, back from -Z, left from -X and right from +X, with +Y up; top is seen from +Y and bottom from -Y, with +X right and the front toward the bottom (top) or the top (bottom) of the image. Both the projection and the view's subject (alpha above half, else pixels differing from the corner colour; 8-bit PNG only) are cropped to their tight bounds, scaled uniformly into a 256 px canvas and compared, so a view's resolution and the mesh's scale do not matter but its proportions do. A gate that cannot be evaluated (no such view, an unreadable image) fails with the reason; nothing is skipped silently. The report is `assets/models/<slug>/checks/<mesh id>.json` (every gate with value, limit and detail), referenced from a `checks` record in the manifest; the stage becomes `checked` only when every gate passes. The command prints `ok: false`, lists `failed` and exits 1 when any gate fails.

## Windows setup

1. Install uv from PowerShell: `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`.
2. Install Blender 4.5 LTS (the portable zip is fine) and Godot 4.7.2 **standard** (not the .NET build). The exact versions are in `versions.yaml`.
3. Create `tools/asset_pipeline/.env` with the tool paths, forward slashes and no quotes, plus any API keys:

   ```
   ASSET_BLENDER_BIN=C:/Tools/blender-4.5.3-windows-x64/blender.exe
   GODOT=C:/Tools/Godot_v4.7.2-stable_win64.exe
   ```
4. Optional: to use real services on this machine without editing the committed `providers.yaml`, copy `providers.local.example.yaml` to `providers.local.yaml` (git-ignored) and keep the lines you want, e.g. `image: google`, `three_d: tripo`, `prompt_writer: claude-cli`. It holds a `selection:` block only and overrides the committed selection key by key. Precedence: command flag (`--image-provider`, `--3d-provider`, `--prompt-writer`), then `providers.local.yaml`, then `providers.yaml`. A name that is not configured in `providers.yaml` is an error. `asset doctor` and `asset list` print the effective selection and where each value came from (`selected`, `selected_source`). Without the file (CI, cloud agents) nothing changes. The Studio's Concept view has a Prompt writer dropdown that defaults to this selection.
5. From `tools/asset_pipeline`, run `uv run asset doctor`. It fails the required check for any other Blender or Godot version and names the version found and expected.
- Mock flow: the `mock` 3D provider returns a closed, single-part, vertex-coloured ~3.4k-triangle fish-like mesh (`fixture_mesh.mock_mesh`), and the `mock` image provider's turnaround edits return that mesh's silhouettes (alpha PNGs, same axes as `check`). `new → concept → lock → turnaround → brief → to3d → cleanup → check → export` therefore passes every `creature` gate with no API keys (the Blender step needs Blender, as ever).
